# Device Sync Design

**Date:** 2026-05-23  
**Feature:** Cross-device sync of reading progress via Cloudflare Worker + KV  
**Scope:** `completedTasks` only (preferences stay local per device)

---

## Overview

Users can opt-in to sync their Bible reading progress across devices (desktop + mobile). A shared `syncId` (UUID) identifies the sync group. A per-device `deviceId` is used internally to prevent write amplification. The backend is a Cloudflare Worker with KV storage. Manual push/pull — no automatic sync in v1.

---

## Architecture

```
Browser (Device A)                Browser (Device B)
localStorage                      localStorage
completedTasks                    completedTasks
     │  ▲                              │  ▲
push │  │ pull                    push │  │ pull
     ▼  │                              ▼  │
src/utils/sync.ts               src/utils/sync.ts
pushSync() / pullSync()         pushSync() / pullSync()
          │                               │
          └──────── fetch (UUID in URL) ──┘
                          │
               Cloudflare Worker (edge)
               GET  /sync/:uuid → KV read
               PUT  /sync/:uuid → KV union+write
                          │
                    KV Store
                    key: syncId
                    val: JSON
```

## Data Model

### AppSettings additions (`src/types.ts`)

```ts
syncId:       string | null   // shared across linked devices; null = sync disabled
deviceId:     string          // per-device UUID, auto-generated silently on first load
lastSyncedAt: string | null   // ISO timestamp of last successful sync
```

### KV value schema

```json
{
  "version": 1,
  "completedTasks": {
    "2026-01-01": ["Mt1"],
    "2026-01-02": ["Mk1", "Mk2"]
  },
  "updatedAt": "2026-05-23T04:00:00.000Z",
  "lastDeviceId": "per-device-uuid"
}
```

`completedTasks` is stored as a date-keyed map for easier future pruning. Internally all merge operations use `Set<string>` with flat IDs (`"2026-01-01:Mt1"`). Conversion happens only at KV boundaries.

---

## Identity Model

Two distinct UUIDs per device:

| Field | Scope | Generated by | Purpose |
|---|---|---|---|
| `syncId` | Shared across devices | User (Device 1 only) | KV key; identifies sync group |
| `deviceId` | Per-device | Auto on first load | Write loop guard (`lastDeviceId`) |

`syncId` is opt-in and never auto-generated silently. `deviceId` is always auto-generated, never shown to user.

## SyncId Setup Flow

**Device 1:**
1. User opens Settings → Sync section
2. Taps "啟用同步"
3. App calls `crypto.randomUUID()` → stored as `syncId`
4. UUID shown with copy button + QR code

**Device 2+:**
1. User opens Settings → Sync section
2. Taps "輸入現有 ID" or scans QR code
3. UUID stored as `syncId`
4. Immediate Pull triggered to bootstrap local state

**Disable:** Clears `syncId` from AppSettings. Does NOT delete KV data — user can re-enter the same ID later to resume.

## Sync Flows

### Internal merge

All merge operations normalize to `Set<string>` of flat IDs:

```ts
// KV map → flat Set
kvMapToSet({ "2026-01-01": ["Mt1"] }) → Set { "2026-01-01:Mt1" }

// flat Set → KV map
setToKvMap(Set { "2026-01-01:Mt1" }) → { "2026-01-01": ["Mt1"] }

// merge
union(localSet, remoteSet) = new Set([...localSet, ...remoteSet])
```

### Pull

1. Fetch remote KV → decode to `Set<string>`
2. `union(local, remote)` → `merged`
3. Update local `completedTasks` + `lastSyncedAt`
4. If `merged.size > remote.size && remote.lastDeviceId !== deviceId` → reconciliation push (heal stale remote)

### Push

1. Fetch remote KV → decode to `Set<string>`
2. `union(local, remote)` → `merged`
3. Update local `completedTasks` + `lastSyncedAt`
4. PUT `{ version, completedTasks: setToKvMap(merged), updatedAt: now, lastDeviceId: deviceId }` to KV

Push always pull-first — no data loss possible. `updatedAt` is informational (clock skew detection/debugging), not used for conflict resolution.

### Write amplification guard

Reconciliation push only fires when `remote.lastDeviceId !== deviceId`. If I was the last writer, skip — prevents A→B→A→B echo loops.

## Worker API (`worker/index.ts`)

```
GET  /sync/:uuid
  → 200 { version, completedTasks, updatedAt, lastDeviceId }
  → 404 { error: "not found" }  (new UUID, no data yet)

PUT  /sync/:uuid
  body: { version, completedTasks, updatedAt, lastDeviceId }
  → reads existing KV
  → unions completedTasks server-side (race condition safety)
  → writes merged back
  → 200 { version, completedTasks, updatedAt, lastDeviceId }
```

Worker does server-side union on PUT — safe if two devices push simultaneously.

```

**Enabled, idle**

[↑ 推送]   [↓ 拉取]   [停用]
```

```
[↑ 推送中…]   ← spinner, buttons disabled
```

**Error**
```
⚠ 同步失敗：網路錯誤   [重試]
```

Uses existing token system (`T`, `A`, `F`) — no new design primitives. QR encodes raw UUID string.

## Error Handling

| Scenario | Behavior |
|---|---|
| Network failure | Inline error shown, no state change |
| KV not found (new UUID) | Treat as empty remote, push local data |
| Worker 5xx | Show error, retry button |
| Malformed KV response | Log + treat as empty remote, don't corrupt local |
| `crypto.randomUUID` unavailable | Fallback to manual UUID input only |
| Clock skew | Log warning, still merge (union always safe) |

Local `completedTasks` never modified on error. State updated only after confirmed successful sync.

## Migration Path to Supabase

All app-facing sync calls go through `src/utils/sync.ts`. Migration to Supabase (e.g., for auth) requires:
1. Swap fetch URLs + add `Authorization` header in `sync.ts`
2. Create Supabase table: `sync_data(id uuid PK, completed_tasks jsonb, updated_at timestamptz, last_device_id text)`
3. Users re-push from local device to populate new backend

Estimated effort: ~1 day. No changes to App.tsx or types.ts needed.
